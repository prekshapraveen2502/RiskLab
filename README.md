# RiskLab

A portfolio risk pipeline that computes Value at Risk and Expected Shortfall — and then tests whether those numbers actually hold up out of sample.

Computing a VaR number is a one-line quantile. The harder question is whether the number is trustworthy, which is what most of this project is about: rolling out-of-sample forecasts with no lookahead bias, breach detection, and a Kupiec unconditional coverage test with a real p-value.

---

## Results

Five-ETF portfolio, 2018-01-02 to 2026-08-31, 2,176 daily returns.

| Metric | Value |
|---|---|
| Historical VaR (95%) | **1.1643%** |
| Expected Shortfall (95%) | **1.7895%** |
| Evaluated out-of-sample forecasts | 1,926 |
| Breaches observed | 105 |
| Observed breach rate | **5.4517%** |
| Expected breach rate | 5.0000% |
| Kupiec LR statistic | 0.804760 |
| Kupiec p-value | **0.369674** |
| Reject null at 5% | **No** |

The breach frequency is statistically consistent with 95% coverage. That means unconditional coverage was not rejected — it is not evidence that the model is correct. See [Limitations](#limitations).

Figures come from `data/processed/risk_summary.json`, regenerated by `run_pipeline.py`.

## Quickstart

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python run_pipeline.py             # fetch data, compute risk, backtest, persist
python -m pytest -q                # 238 tests, no network required
```

Requires Python 3.11+ (developed on 3.14).

`run_pipeline.py` prints a summary and writes six files under `data/`. Only the JSON summary is committed; the Parquet outputs are gitignored and regenerate on each run.

## How it works

```
config/portfolio.csv
        │
        ▼
  ingestion ──────── MarketDataProvider protocol (yfinance adapter)
        │
        ▼
  validation ─────── portfolio weights + market data quality gates
        │
        ▼
  transformation ─── prices → asset returns → weighted portfolio return
        │
        ▼
  risk ───────────── Historical VaR · Expected Shortfall · 250-day rolling VaR
        │
        ▼
  backtesting ────── breach detection → summary → Kupiec coverage test
        │
        ▼
  persistence ────── 5 Parquet files + risk_summary.json
        │
        ▼
  ai layer ───────── 5 read-only tools over the persisted outputs
```

Orchestration is a single function, `run_analysis()` in `run_pipeline.py`. Each stage is a pure function, so the pipeline is a straight line with no hidden state.

## Design decisions

**No lookahead bias, and it's tested.** A naive `.rolling(250).quantile()` includes the current day in its own forecast window, which quietly invalidates the entire backtest. `calculate_rolling_historical_var` applies `shift(1)` first, so every forecast uses strictly prior data. This isn't just asserted in a comment — `test_rolling_var_has_no_lookahead_bias` perturbs one day's actual return and asserts that day's forecast is unchanged while the following day's does change.

**Bad data fails loudly; nothing is silently repaired.** There is no imputation, no forward fill, and no row-dropping anywhere in the pipeline. `pct_change(fill_method=None)` prevents a missing price from becoming a fake 0% return. `min_count=len(weights)` prevents a partial portfolio from being summed as if it were whole. If any portfolio return is missing, the pipeline raises with the count and the first offending date. In a risk context a silently wrong number is worse than no number.

**Breach flags carry three states, not two.** A day is a breach, not a breach, or not evaluable because the 250-day window hadn't filled yet. Using pandas' nullable `boolean` dtype keeps warm-up days as `pd.NA` so they're excluded from the breach-rate denominator. Collapsing them to `False` would have reported 4.83% instead of the true 5.45% — a bug that makes the model look better than it is.

**External data sits behind a protocol.** `MarketDataProvider` is a one-method `typing.Protocol`, and `run_analysis(provider=...)` accepts any implementation. Tests inject a `FakeProvider`, so the full pipeline is exercised with zero network calls and the suite runs in under three seconds.

**The LLM layer cannot compute anything.** The agent reads persisted outputs through five read-only tools and never recomputes a figure. Tool access is allowlisted — an unregistered name or an unexpected argument raises — and the tools have no write path. Tests snapshot the size and modification time of all four persisted data files and assert both are unchanged after every tool is called and after a full agent run.

## Testing

238 tests, no network calls anywhere in the suite.

| Area | Tests |
|---|---|
| Backtesting and Kupiec | 37 |
| AI tools and agent loop | 64 |
| Historical VaR / ES | 21 |
| Pipeline orchestration | 18 |
| Provider adapters | 32 |
| Rolling VaR | 15 |
| Persistence round-trip | 15 |
| Returns and validation | 26 |
| Reporting | 10 |

The Kupiec implementation is tested against hand-computed values at known inputs rather than against its own output — at exactly the expected breach rate the LR statistic must be 0 and p must be 1, and both are asserted. Degenerate cases (zero breaches, all breaches) are covered because the log-likelihood has a `log(0)` term that must be guarded.

Run with `python -m pytest`. The `-m` form is required because there is no packaging config placing the repository root on `sys.path`.

## The validation agent

An optional layer that lets a language model answer questions about the risk results by calling deterministic tools, rather than by doing arithmetic itself.

> **Status: implemented and tested, not yet run against a live model.** The agent loop, both provider adapters, and the tools are covered by tests that use scripted providers and stubbed SDK responses, so the request/response handling and tool dispatch are exercised. No request has been sent to the Gemini or OpenAI APIs yet. There is no saved agent transcript, and no claim here about the quality of the model's answers. The default model names are configuration values and haven't been checked against a live endpoint.

```bash
export GEMINI_API_KEY=...          # or OPENAI_API_KEY
export RISKLAB_LLM_PROVIDER=gemini # gemini (default) or openai
python run_validation_agent.py --verbose
```

Five registered tools: `get_portfolio_risk_overview`, `get_model_validation_results`, `get_var_breach_details`, `get_worst_portfolio_days`, `get_period_risk_snapshot`. The model chooses which to call; the agent loop executes them and feeds results back, up to a six-step cap.

Credentials are read only from environment variables and are never written to the repository or printed. Without a key the entry point makes no LLM call: it warns, then prints and saves a deterministic validation report built directly from `risk_summary.json` (`data/processed/deterministic_validation_report.txt`), with the same Kupiec interpretation and limitations the agent is instructed to follow.

## Limitations

- **Kupiec tests breach frequency, not independence.** It would return the same verdict whether the 105 breaches were spread evenly or clustered in a single month. A Christoffersen independence test is the natural next addition.
- **Historical VaR assumes the sample represents the future** and cannot anticipate a shock without precedent in the data.
- **Expected Shortfall is estimated from a thin tail** — roughly 109 observations at 95% — so it is less stable than the VaR estimate.
- **The LLM agent has only been tested offline.** Its grounding rules (call tools for every number, never recompute, don't treat a non-rejection as proof) are enforced by the system prompt, not checked against the model's output. Until it runs against a real model, how well it follows those rules is unknown.
- **Single-machine and in-memory.** Every run recomputes the full history; there is no incremental or partitioned processing.
- **Analysis dates and the rolling window are constants** in `run_pipeline.py`, not CLI arguments.
- **No data versioning.** Outputs are overwritten in place, so a vendor revising historical prices leaves no trace.
